# 학교장터 계정 입력용 짧은 링크

새 링크 발급 결과는 `/s/{22자 코드}`다. 학교명과 구매 조건이 들어 있는 기존 서명 링크를 별도 `school_store_input_links` 테이블에 보관하고, 짧은 코드는 SHA256 해시로 조회한다. 원본 링크의 서명·만료일·접수 식별번호를 다시 검증한다.

기존 `/school-store/{긴 서명 토큰}`은 같은 주소로 계속 열리고 제출할 수 있다. 기존 링크는 조회 테이블 없이 서명을 직접 검증한다. 동일한 원본의 긴·짧은 링크는 `school-store-input:{id}`를 함께 사용하므로 동시 제출 시에도 최초 접수 1건만 저장한다. 짧게 바꿀 때 만료일을 새로 연장하지 않는다.

관리자 발급 API `POST /api/admin/school-store-links`에 `{ "existingToken": "기존 서명 토큰" }`을 보내면 같은 구매 건의 짧은 링크를 받을 수 있다. 관리자 인증과 원본 서명·만료 검증을 통과해야 하며, 새 구매 건이나 접수는 생성하지 않는다.

## 배포 순서

1. `node scripts/apply-0029.mjs --env-file <기존 환경 파일>`로 트랜잭션 안에서 새 테이블과 제약을 검사한다. 기본 실행은 롤백한다.
2. 확인한 같은 DB에 `CONFIRM_SCHOOL_STORE_LINKS_APPLY=confirmed node scripts/apply-0029.mjs --env-file <기존 환경 파일> --apply`로 추가 테이블을 적용한다. 기존 주문·청구·결제 행은 변경하지 않는다.
3. 기존 Git 연동 절차로 코드를 배포한다.
4. 관리자 링크 발급이 `/s/` URL을 반환하는지 확인하고, 긴·짧은 링크의 학교명과 구매 수량이 같은지 확인한다.

저장 실패 시 링크를 반환하지 않고, 조회 장애는 제출 API에서 503으로 안내한다. 잘못되었거나 만료된 링크는 접수하지 않는다. 새 테이블 적용 후 이전 코드로 되돌리더라도 긴 링크는 계속 작동한다.
