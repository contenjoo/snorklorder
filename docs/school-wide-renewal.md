# 학교 단체 이용권 연장

기존 학교 단체 구매를 새 계정 업그레이드와 구분해 연장한다. 기존 `account_requests`의 `type=extension`, `accountType=school`을 사용하므로 DB 마이그레이션은 없다.

## 관리자 사용 순서

1. **학교 관리**에서 학교를 검색하고 **단체 연장**을 누른다.
2. 국문·영문 학교명을 확인한다. 국문명과 영문명이 모두 일치하는 이전 학교 단체 요청이 있으면 기존 대표 계정과 구매처를 불러온다. 교사별 계정·취소·보관 기록은 자동 복사하지 않는다.
3. 기존 학교 이용권을 식별할 **학교 대표 계정 이메일**, 올해 구매처, **새 이용 종료일**, 결제 기간을 확인한다. 교사 전체 명단을 입력할 필요는 없다. 학교 수는 **1교**로 고정된다.
4. **연장 요청 저장**을 누른다. 새 작성 중 요청이 생성되며 과거 요청의 인보이스·결제·완료 확인 기록은 복사하지 않는다.
5. 새 요청 행의 **미리보기**에서 영문 학교명, 학교 전체 이용권 범위와 종료일을 검토하고 **발송하기**를 누른다.

현재 서비스의 기존 동작대로, 마지막 단계는 Jon의 `/partner` Billing 화면에 요청을 등록한다. 건별 Jon 이메일은 보내지 않으며, 인보이스 필요가 켜져 있으면 현재 월 2회 통합 청구 주기에 편입된다. Jon 확인 화면에서도 학교 전체 연장·1교·종료일·기간을 볼 수 있다.

일반 **계정 요청 → 새 요청 → 연장 → 학교 전체 (School)** 경로도 같은 검증과 본사 등록 흐름을 사용한다.

## 광신방송예술고등학교

2026-10-28 읽기 조회에서 현재 학교 ID `141`의 국문명은 `광신방송예술고등학교`, 영문명은 `Kwangshin Broadcasting Arts High School Library`였다. 관리자 진입 경로는 `/admin/accounts?renewSchool=141`이다. 이전 학교 전체 계정 요청은 이 저장소의 연결 DB에서 찾지 못했으므로 대표 계정과 새 종료일을 직접 확인해야 한다.

기존 메일에 학교 단체 계정 사용 근거는 있지만, 올해 정확한 이용 종료일은 확인되지 않았다. S2B 납품요청일을 이용권 종료일로 대입하지 않는다. 이름이 비슷한 별도 학교 레코드도 발견했으며 이번 작업에서는 통합·수정하지 않았다.

## 검증과 적용 범위

- 존재하지 않는 날짜, 종료일 누락, 학교 수량이 1교가 아닌 요청은 생성·수정·본사 등록 전에 차단한다.
- 이전 초안의 상태만 바꿔 본사 화면에 올리는 경로에도 같은 검증을 적용한다. 기존 인보이스 건의 결제 상태 갱신은 유지한다.
- 모의 학교·예시 계정 `renewal-fixture@example.com`과 예시 종료일 `2027-11-01`로 학교 목록 → 폼 → 누락 오류 → 저장 → 영문 미리보기 → 본사 등록 상태 전환 → 확인 화면을 검증했다. 예시 날짜는 실제 계약 종료일이 아니다.
- 전체 계약 검사 223개 중 219개 통과, 환경 의존 검사 4개 기본 건너뜀. Production 빌드(타입 검사 포함), 변경 파일 ESLint, `git diff --check` 통과. 실제 휴대폰 검사는 하지 않았다.
- 운영 DB 변경, 실제 연장 신청, 외부 이메일 발송, 운영 배포는 실행하지 않았다.
